# Dahua ক্যামেরা + DVR → ওয়েবঅ্যাপ লাইভ (DigitalOcean VPS, CGNAT, শুধু ফোন)

**এই ডকে যা আছে:** আপনার *আজকের* সেটআপ দিয়ে — Dahua ONVIF ক্যামেরা + Dahua DVR,
একটা DigitalOcean VPS, ISP থেকে **পাবলিক IP নেই**, আর সব কাজ **ফোন থেকেই** — ওয়েবঅ্যাপে
লাইভ দেখানোর একমাত্র কার্যকর রাস্তা, ধাপে ধাপে, আর কোথায় কী বদলাতে হবে।

> **অন্য ডকগুলোর সাথে সম্পর্ক:** `cctv-live-start-here.md` হলো সাধারণ সিদ্ধান্ত-গাছ
> (Imou ক্যামেরা ধরে লেখা)। এটা তার **CGNAT + Dahua DVR** শাখাটা, আজকের তথ্য দিয়ে
> আপডেট করা। দ্বিমত হলে **এই ডকটাই আপনার জন্য সত্য** — কারণ এটা আপনার ডিভাইস আর
> আপনার নেটওয়ার্ক ধরে লেখা।

## ০. এক লাইনে সিদ্ধান্ত

> **পথ নেই — কারণ এখনো প্রমাণ হয়নি DVR নিজে পুশ করতে পারে।** পরের ১০ মিনিটে সেটাই
> আগে যাচাই করুন। পারলে দিনের কাজ শেষ; না পারলে §৩-এর তিনটার একটা।

| যা যাচাই করবেন | কোথায় | তারপর |
|---|---|---|
| DVR-এ **RTMP push** আছে কি? | §১ | ✅ থাকলে → §২ (সবচেয়ে সহজ, খরচ শুধু VPS) |
| না থাকলে | §৩ | ফোন/Pi restreamer, অথবা ISP-র পাবলিক IP, অথবা Imou ক্যামেরা |

**যা কখনোই হবে না (আবার ভাববেন না):** VPS থেকে সোজা `rtsp://192.168.x.x` টানা।
`192.168.x.x` আপনার ঘরের ভেতরের ঠিকানা; VPS সেটা চিনতেই পারে না। আর ISP-র CGNAT
বাইরে থেকে ভেতরে ঢোকার পথটাই বন্ধ রাখে। VPS যত দামিই হোক, এটা বদলাবে না।

## ১. 🔴 প্রথম ১০ মিনিট — DVR-এ RTMP আছে কি না (ফোন থেকেই)

এটাই পুরো সিদ্ধান্তের একমাত্র প্রশ্ন। **হ্যাঁ হলে বাকি সব সহজ।**

### ১.১ DVR-এর IP বের করুন
- রাউটারের অ্যাডমিন প্যানেল (ব্রাউজারে `192.168.0.1` বা `192.168.1.1`) → **DHCP Client List**
- সেখানে `Dahua` / MAC দেখে IP নিন — যেমন `192.168.1.108`
- বা DMSS অ্যাপ → ডিভাইস → সেটিংস → ডিভাইস ইনফো → IP

### ১.২ ফোনের ব্রাউজারে DVR-এর পেজ খুলুন
```
http://192.168.1.108
```
লগইন করুন (Dahua-র পুরোনো ফার্মওয়্যারে `admin/admin` চলে; না হলে DMSS-এর পাসওয়ার্ড)।

> ⚠️ পুরোনো Dahua ওয়েব UI-তে Chrome/Edge-এ প্লাগইন বা "unsafe" ওয়ার্নিং আসতে পারে।
> সেটা স্বাভাবিক — আমাদের দরকার শুধু **সেটিংসের মেনু**, লাইভ ভিউ নয়।

### ১.৩ ঠিক এই মেনুগুলো খুঁজুন
```
Setup → Network → Platform Access   (কিছু ফার্মওয়্যারে: Network → Port)
```
ট্যাবগুলো দেখুন: `TCP/IP` · `Port` · `DDNS` · `Email` · **`RTMP`** · `P2P`

| যা দেখলেন | মানে | যান |
|---|---|---|
| ✅ **RTMP** ট্যাব আছে | DVR নিজেই VPS-এ পুশ করতে পারবে | **§২** |
| ❌ নেই, শুধু RTSP/P2P | এই রেকর্ডার পুশ করতে পারে না | **§৩** |
| 🤔 মেনু খুঁজেই পাচ্ছি না | §১.৪-এর বিকল্প পথ | নিচে |

### ১.৪ মেনু না পেলে — ৩টা বিকল্প পথ

**(ক) Network → Advanced → Protocol / "Network Protocol" তালিকা**
আপনার XVR-এ এই তালিকাই ছিল নির্ণায়ক:
`HTTP; HTTPS; TCP/IP; IPv4; RTSP; UDP; SMTP; NTP; DHCP; DNS; DDNS; P2P`
— এখানে **RTMP লেখা না থাকলে** ডিভাইসটা পুশ করতে পারে না, মেনু লুকানো থাকলেও না।

**(খ) ডিভাইসের মডেল + ফার্মওয়্যার লিখে নিন**
Setup → System → Version/Info। মডেল (যেমন `DH-XVR1B16-I-SSI`) আর ফার্মওয়্যার ভার্সন
লিখে রাখুন — Dahua-র ফিচার লিস্টের সাথে মিলিয়ে দেখতে Workbench লাগবে না, Dahua-র
নিজের spec sheet-ই যথেষ্ট। সাধারণ নিয়ম:

| সিরিজ | RTMP push |
|---|---|
| DH-XVR1B / XVR4B (সস্তা, ১০৮০p) | ❌ প্রায়ই নেই |
| DH-XVR5 / XVR7 / NVR4 / NVR5 | ✅ প্রায়ই আছে |
| Dahua **ONVIF ক্যামেরা** (আলাদা) | ⚠️ নির্ভর করে মডেলে; অনেক IP ক্যামেরায় RTMP নেই |

**(গ) ফোনের অ্যাপে দেখুন**
DMSS → ডিভাইস → সেটিংস → **প্ল্যাটফর্ম অ্যাক্সেস**। কিছু ফার্মওয়্যারে এই অপশনটা
শুধু অ্যাপ থেকেই দেখা যায়, ওয়েব UI-তে লুকানো থাকে।

### ১.৫ ফলাফল লিখে রাখুন
```
DVR মডেল      : ______________________
ফার্মওয়্যার   : ______________________
RTMP আছে?     :  হ্যাঁ  /  না
```
এই চার লাইনই ঠিক করে দেবে বাকি সব।

## ২. ✅ RTMP আছে — DigitalOcean VPS-এ পুশ (পাবলিক IP লাগবে না)

**কেন এটা CGNAT-এ চলে:** CGNAT শুধু **বাইরে থেকে ভেতরে** ঢুকতে দেয় না।
**ভেতর থেকে বাইরে** যাওয়া কখনো আটকায় না — DMSS অ্যাপ ঠিক এভাবেই কাজ করে।
DVR নিজেই VPS-এ সংযোগ খুলে ছবি পাঠাবে, তাই "কেউ ভেতরে ঢুকছে" বলে কিছু নেই।

```
DVR ──RTMP push (বাইরে যাচ্ছে)──► DigitalOcean VPS ──HLS──► দর্শকের ব্রাউজার
                                      └─ MediaMTX + Caddy (TLS)
```

### ২.১ VPS-এ ফায়ারওয়াল — এই ধাপটা বাদ দিলে কিছুই কাজ করবে না
DigitalOcean → Droplet → **Networking → Firewalls** (বা droplet-এ `ufw`):

| পোর্ট | কেন |
|---|---|
| **TCP 1935** | DVR এখানেই পুশ করবে ← **সবচেয়ে বেশি ভুলে যাওয়া পোর্ট** |
| TCP 80, 443 | Caddy-র Let's Encrypt সার্টিফিকেট + দর্শকদের HLS |
| TCP 22 | SSH (শুধু আপনার IP থেকে) |

> ⚠️ VPS-এ `ufw` চালু থাকলে `ufw allow 1935/tcp`-ও লাগবে। দুই জায়গাতেই খুলুন।
> যাচাই: ফোনের **মোবাইল ডাটা** দিয়ে (WiFi বন্ধ) <https://canyouseeme.org> → port `1935`
> → "Success" মানে পোর্ট খোলা; "Connection refused" মানে এখনো বন্ধ।

### ২.২ ডোমেইন → VPS
`stream.yourdomain.com` এর জন্য একটা **A record** → VPS-এর IP।
(Cloudflare-এ ডোমেইন থাকলে প্রোক্সি **DNS only** / কমলা মেঘ বন্ধ রাখুন —
ভিডিও Cloudflare-এর ফ্রি প্ল্যানের শর্ত ভাঙে।)

### ২.৩ repo + `.env` (ফোনের SSH থেকেই)
```bash
ssh root@<VPS-IP>
apt update && apt install -y docker.io docker-compose-plugin git
git clone https://github.com/farukhossain25/AGRO.git && cd AGRO
```

`.env` ফাইল বানান:
```bash
cat > .env <<'EOF'
STREAM_PUBLIC_HOST=stream.yourdomain.com
STREAM_EDGE_SECRET=এখানে_১৬_অক্ষরের_র‍্যান্ডম
ACME_EMAIL=you@yourdomain.com
EOF
```
> র‍্যান্ডম স্ট্রিং বানাতে: `openssl rand -hex 8`

### ২.৪ পুশ পাবলিশারের পাসওয়ার্ড বদলান — **করে ফেলুন**
`mediamtx.yml`-এ `publishPass: CHANGE_ME_PUBLISH_PASSWORD`। এটা **আসল পাসওয়ার্ড**,
প্লেসহোল্ডার নয় — যেই এটি জানে সে আপনার ভিউয়ারদের দেখানো স্ট্রিম হাইজ্যাক করতে পারে।

```bash
nano mediamtx.yml      # pathDefaults → publishPass: একটা লম্বা র‍্যান্ডম শব্দ
```
একই শব্দটা DVR-এর RTMP সেটিংয়েও দিতে হবে (§২.৬)।

### ২.৫ `mediamtx.yml`-এ পুশ-পাথটা আগেই দেওয়া আছে
repo-তে `dvr-cam-01` নামে একটা entry আছে:
```yaml
  dvr-cam-01:
    source: publisher     # ← MediaMTX কারও পেছনে ছুটবে না, কেউ পুশ করবে
```
**এই নামটাই পরে ক্যামেরার `stream_key` হবে** — হুবহু লিখে রাখুন।
একাধিক চ্যানেল চাইলে:
```yaml
  dvr-cam-01:
    source: publisher
  dvr-cam-02:
    source: publisher
```

### ২.৬ DVR-এ পুশ সেট করুন (ফোনের ব্রাউজারে)
```
Setup → Network → Platform Access → RTMP
```
| ফিল্ড | মান |
|---|---|
| Enable | ✓ |
| Address Type | **Custom** |
| Custom Address | `rtmp://<VPS-IP>:1935/dvr-cam-01` |
| Username | `publisher` |
| Password | §২.৪-এ যেটা দিলেন |

> কিছু ফার্মওয়্যারে address আর stream key আলাদা: তখন address =
> `rtmp://<VPS-IP>:1935/dvr-cam` আর key = `01`। দুটোতেই একই URL দাঁড়ায়।

**সেভ → রিবুট লাগতে পারে।** তারপর যাচাই:

### ২.৭ যাচাই — ৩টা কমান্ড (ফোনের SSH-এ)
```bash
cd ~/AGRO
docker compose -f docker-compose.stream-vps.yml --profile public up -d

# ১) কনটেইনার দুইটা চালু?

# ৩) ছবি বের হচ্ছে?  → 200 হলে স্ট্রিম জীবন্ত

```
| ফল | মানে |
|---|---|
| লগে `is publishing` + `200` | ✅ স্ট্রিম এসেছে |
| লগে কিছু নেই | DVR পুশ করছে না — URL/পোর্ট/পাসওয়ার্ড আবার দেখুন |
| `401` | পাসওয়ার্ড ভুল (publishUser/publishPass) |
| `404` | path নাম মেলেনি (`dvr-cam-01` বানান) |

## ৩. ❌ RTMP নেই — তাহলে তিনটাই বাকি

### ৩.১ 🥇 ফোন/Pi restreamer (CGNAT-এও চলে, খরচ ~৳০)

```
DVR ──RTSP (ঘরের ল্যান)──► পুরোনো ফোন/Pi ──SRT push (বাইরে)──► VPS ──► দর্শক
```
কেন চলে: push আবার বাইরের দিকে — CGNAT বাধা দেয় না।
কেন সবসময় ভালো নয়: **ক্যামেরা সাইটে ২৪/৭ একটা ডিভাইস বাঁচিয়ে রাখতে হবে**।
বিদ্যুৎ/ইন্টারনেট গেলে ছবি যাবে। ১০ W × ২৪/৭ ≈ **৳৬৫/মাস** বিদ্যুৎ।

**সেটআপ (ফোন থেকে করা যায়):**
1. পুরোনো Android ফোনে **Termux** (F-Droid থেকে) ইনস্টল
2. VPS-এ SRT পোর্ট খুলুন — `docker-compose.stream-vps.yml`-এ `8890:8890/udp`
   কমেন্ট খুলে দিন, আর DO Firewall-এ **UDP 8890**
3. `mediamtx.yml`-এ আরেকটা পুশ-পাথ: `dvr-cam-01` (SRT-ও একই path-এ পাবলিশ হয়)
4. ফোনে:
```bash
pkg install ffmpeg -y
ffmpeg -rtsp_transport tcp \
  -i "rtsp://admin:<DVR-পাসওয়ার্ড>@192.168.1.108:554/cam/realmonitor?channel=1&subtype=1" \
  -c copy -f mpegts \
  "srt://<VPS-IP>:8890?streamid=publish:dvr-cam-01&passphrase=<publishPass>"
```
5. Termux-এ `termux-wake-lock` চালু রাখুন, ফোনে চার্জার লাগিয়ে রাখুন

> এতে ট্রান্সকোডিং নেই (`-c copy`) — পুরোনো ফোনেও CPU লাগে না।
> DVR-এর সাবস্ট্রিম **H.264** হতে হবে (H.265 হলে ব্রাউজারে চলবে না)।

### ৩.২ 🥈 ISP থেকে পাবলিক IP

CGNAT-এর একমাত্র আসল সমাধান ISP-র হাতে। কল/মেসেজ:

> আসসালামু আলাইকুম। আমার কানেকশনে WAN IP `10.x.x.x` (private) আসছে,
> মানে আমি CGNAT-এর পিছনে। CCTV বাইরে থেকে দেখতে **real public IPv4** দরকার।
> PPPoE কানেকশনে এটা দেওয়া সম্ভব কি? চার্জ কত?

পেলে: রাউটারে `554 → DVR-IP:554` ফরওয়ার্ড → `mediamtx.yml`-এ
`source: rtsp://admin:<pass>@<পাবলিক-IP>:554/cam/realmonitor?channel=1&subtype=1`
→ VPS নিজেই টানবে। **কিন্তু তখন VPS-টা কেন?** — কারণ ব্রাউজার RTSP চালাতে
পারে না; RTSP→HLS বদলাতে মাঝখানে MediaMTX লাগবেই।

> ⚠️ "পোর্ট খুলে দিন" বলবেন না — ISP রাউটারে ঢুকবে না। শুধু **public IP** চাইবেন।

### ৩.৩ 🥉 ক্যামেরা বদলানো (Imou)

Dahua DVR-এর বদলে **Imou** ক্যামেরা নিলে ক্লাউড পথ খোলে (`cloud_provider = imou`) —
VPS, পাবলিক IP, ফোন-বক্স কিছুই লাগে না। কিন্তু **প্রতি দর্শক-ঘণ্টায়** Imou-র
ট্রাফিক বিল ($0.25/GB) — ১০ জন ২৪/৭ = ~৳৫০,০০০/মাস। শুধু মাঝেমধ্যে দেখার জন্য ঠিক।

> আপনার DVR + ক্যামেরা **আগেই আছে** — তাই ৩.১ সবচেয়ে বাস্তব। টাকা খরচ হবে শুধু VPS-এ।

## ৪. খরচ — বাস্তব হিসাব

| খরচ | পরিমাণ |
|---|---|
| DigitalOcean droplet (১ GB) | **$৬/মাস ≈ ৳৭৩০** (আপনার আছে) |

**বাস্তব দর্শক-লোড** (1 লাখ ভিজিট/মাস ধরে):
```
১,০০,০০০ ভিজিট → ~৫০০ ভিজিট/ঘণ্টা → ৩% ক্যামেরা খোলে → ০.২ জন একসাথে
```
অর্থাৎ DigitalOcean-এর ১ TB কোটা **যথেষ্ট**। ২৪/৭ ৬ জনের বেশি একসাথে দেখলে
তবেই overage — তখন droplet বড় করুন বা Oracle Free (১০ TB) ভাবুন।

## ৫. যা ইতিমধ্যেই তৈরি আছে (কোড বদলাতে হবে না)

| জিনিস | কোথায় |

| প্লেয়ার | `components/live/live-stream.tsx` (hls.js, সাবস্ক্রিপশন-বিহীন) |
| অ্যাডমিন ফর্ম | `/foisal/cameras` |

**কোনো SQL লাগবে না** — `cameras.is_premium` কলামটা `03_catalog_tables.sql`-এ
আগেই আছে (ডিফল্ট `true`), তাই পুরোনো ডাটাবেসেও কাজ করবে।
