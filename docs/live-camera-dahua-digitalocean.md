# Dahua ক্যামেরা + DVR → ওয়েবঅ্যাপ লাইভ (DigitalOcean VPS, CGNAT, শুধু ফোন)

**এই ডকে যা আছে:** আপনার *আজকের* সেটআপ দিয়ে — Dahua ONVIF ক্যামেরা + Dahua DVR,
একটা DigitalOcean VPS, ISP থেকে **পাবলিক IP নেই**, আর সব কাজ **ফোন থেকেই** — ওয়েবঅ্যাপে
লাইভ দেখানোর একমাত্র কার্যকর রাস্তা, ধাপে ধাপে, আর কোথায় কী বদলাতে হবে।

> **অন্য ডকগুলোর সাথে সম্পর্ক:** `cctv-live-start-here.md` হলো সাধারণ সিদ্ধান্ত-গাছ
> (Imou ক্যামেরা ধরে লেখা)। এটা তার **CGNAT + Dahua DVR** শাখাটা, আজকের তথ্য দিয়ে
> আপডেট করা। দ্বিমত হলে **এই ডকটাই আপনার জন্য সত্য** — কারণ এটা আপনার ডিভাইস আর
> আপনার নেটওয়ার্ক ধরে লেখা।

## ০. এক লাইনে সিদ্ধান্ত

> **পথ নেই — কারণ এখনো প্রমাণ হয়নি DVR নিজে পুশ করতে পারে।** পরের ১০ মিনিটে সেটাই
> আগে যাচাই করুন। পারলে দিনের কাজ শেষ; না পারলে §৩-এর তিনটার একটা।

| যা যাচাই করবেন | কোথায় | তারপর |
|---|---|---|
| DVR-এ **RTMP push** আছে কি? | §১ | ✅ থাকলে → §২ (সবচেয়ে সহজ, খরচ শুধু VPS) |
| না থাকলে | §৩ | ফোন/Pi restreamer, অথবা ISP-র পাবলিক IP, অথবা Imou ক্যামেরা |

**যা কখনোই হবে না (আবার ভাববেন না):** VPS থেকে সোজা `rtsp://192.168.x.x` টানা।
`192.168.x.x` আপনার ঘরের ভেতরের ঠিকানা; VPS সেটা চিনতেই পারে না। আর ISP-র CGNAT
বাইরে থেকে ভেতরে ঢোকার পথটাই বন্ধ রাখে। VPS যত দামিই হোক, এটা বদলাবে না।

## ১. 🔴 প্রথম ১০ মিনিট — DVR-এ RTMP আছে কি না (ফোন থেকেই)

এটাই পুরো সিদ্ধান্তের একমাত্র প্রশ্ন। **হ্যাঁ হলে বাকি সব সহজ।**

### ১.১ DVR-এর IP বের করুন
- রাউটারের অ্যাডমিন প্যানেল (ব্রাউজারে `192.168.0.1` বা `192.168.1.1`) → **DHCP Client List**
- সেখানে `Dahua` / MAC দেখে IP নিন — যেমন `192.168.1.108`
- বা DMSS অ্যাপ → ডিভাইস → সেটিংস → ডিভাইস ইনফো → IP

### ১.২ ফোনের ব্রাউজারে DVR-এর পেজ খুলুন
```
http://192.168.1.108
```
লগইন করুন (Dahua-র পুরোনো ফার্মওয়্যারে `admin/admin` চলে; না হলে DMSS-এর পাসওয়ার্ড)।

> ⚠️ পুরোনো Dahua ওয়েব UI-তে Chrome/Edge-এ প্লাগইন বা "unsafe" ওয়ার্নিং আসতে পারে।
> সেটা স্বাভাবিক — আমাদের দরকার শুধু **সেটিংসের মেনু**, লাইভ ভিউ নয়।

### ১.৩ ঠিক এই মেনুগুলো খুঁজুন
```
Setup → Network → Platform Access   (কিছু ফার্মওয়্যারে: Network → Port)
```
ট্যাবগুলো দেখুন: `TCP/IP` · `Port` · `DDNS` · `Email` · **`RTMP`** · `P2P`

| যা দেখলেন | মানে | যান |
|---|---|---|
| ✅ **RTMP** ট্যাব আছে | DVR নিজেই VPS-এ পুশ করতে পারবে | **§২** |
| ❌ নেই, শুধু RTSP/P2P | এই রেকর্ডার পুশ করতে পারে না | **§৩** |
| 🤔 মেনু খুঁজেই পাচ্ছি না | §১.৪-এর বিকল্প পথ | নিচে |

### ১.৪ মেনু না পেলে — ৩টা বিকল্প পথ

**(ক) Network → Advanced → Protocol / "Network Protocol" তালিকা**
আপনার XVR-এ এই তালিকাই ছিল নির্ণায়ক:
`HTTP; HTTPS; TCP/IP; IPv4; RTSP; UDP; SMTP; NTP; DHCP; DNS; DDNS; P2P`
— এখানে **RTMP লেখা না থাকলে** ডিভাইসটা পুশ করতে পারে না, মেনু লুকানো থাকলেও না।

**(খ) ডিভাইসের মডেল + ফার্মওয়্যার লিখে নিন**
Setup → System → Version/Info। মডেল (যেমন `DH-XVR1B16-I-SSI`) আর ফার্মওয়্যার ভার্সন
লিখে রাখুন — Dahua-র ফিচার লিস্টের সাথে মিলিয়ে দেখতে Workbench লাগবে না, Dahua-র
নিজের spec sheet-ই যথেষ্ট। সাধারণ নিয়ম:

| সিরিজ | RTMP push |
|---|---|
| DH-XVR1B / XVR4B (সস্তা, ১০৮০p) | ❌ প্রায়ই নেই |
| DH-XVR5 / XVR7 / NVR4 / NVR5 | ✅ প্রায়ই আছে |
| Dahua **ONVIF ক্যামেরা** (আলাদা) | ⚠️ নির্ভর করে মডেলে; অনেক IP ক্যামেরায় RTMP নেই |

**(গ) ফোনের অ্যাপে দেখুন**
DMSS → ডিভাইস → সেটিংস → **প্ল্যাটফর্ম অ্যাক্সেস**। কিছু ফার্মওয়্যারে এই অপশনটা
শুধু অ্যাপ থেকেই দেখা যায়, ওয়েব UI-তে লুকানো থাকে।

### ১.৫ ফলাফল লিখে রাখুন
```
DVR মডেল      : ______________________
ফার্মওয়্যার   : ______________________
RTMP আছে?     :  হ্যাঁ  /  না
```
এই চার লাইনই ঠিক করে দেবে বাকি সব।

## ২. ✅ RTMP আছে — DigitalOcean VPS-এ পুশ (পাবলিক IP লাগবে না)

**কেন এটা CGNAT-এ চলে:** CGNAT শুধু **বাইরে থেকে ভেতরে** ঢুকতে দেয় না।
**ভেতর থেকে বাইরে** যাওয়া কখনো আটকায় না — DMSS অ্যাপ ঠিক এভাবেই কাজ করে।
DVR নিজেই VPS-এ সংযোগ খুলে ছবি পাঠাবে, তাই "কেউ ভেতরে ঢুকছে" বলে কিছু নেই।

```
DVR ──RTMP push (বাইরে যাচ্ছে)──► DigitalOcean VPS ──HLS──► দর্শকের ব্রাউজার
                                      └─ MediaMTX + Caddy (TLS)
```

### ২.১ VPS-এ ফায়ারওয়াল — এই ধাপটা বাদ দিলে কিছুই কাজ করবে না
DigitalOcean → Droplet → **Networking → Firewalls** (বা droplet-এ `ufw`):

| পোর্ট | কেন |
|---|---|
| **TCP 1935** | DVR এখানেই পুশ করবে ← **সবচেয়ে বেশি ভুলে যাওয়া পোর্ট** |
| TCP 80, 443 | Caddy-র Let's Encrypt সার্টিফিকেট + দর্শকদের HLS |
| TCP 22 | SSH (শুধু আপনার IP থেকে) |

> ⚠️ VPS-এ `ufw` চালু থাকলে `ufw allow 1935/tcp`-ও লাগবে। দুই জায়গাতেই খুলুন।
> যাচাই: ফোনের **মোবাইল ডাটা** দিয়ে (WiFi বন্ধ) <https://canyouseeme.org> → port `1935`
> → "Success" মানে পোর্ট খোলা; "Connection refused" মানে এখনো বন্ধ।

### ২.২ ডোমেইন → VPS
`stream.yourdomain.com` এর জন্য একটা **A record** → VPS-এর IP।
(Cloudflare-এ ডোমেইন থাকলে প্রোক্সি **DNS only** / কমলা মেঘ বন্ধ রাখুন —
ভিডিও Cloudflare-এর ফ্রি প্ল্যানের শর্ত ভাঙে।)

### ২.৩ repo + `.env` (ফোনের SSH থেকেই)
```bash
ssh root@<VPS-IP>
apt update && apt install -y docker.io docker-compose-plugin git
git clone https://github.com/farukhossain25/AGRO.git && cd AGRO
```

`.env` ফাইল বানান:
```bash
cat > .env <<'EOF'
STREAM_PUBLIC_HOST=stream.yourdomain.com
STREAM_EDGE_SECRET=এখানে_১৬_অক্ষরের_র‍্যান্ডম
ACME_EMAIL=you@yourdomain.com
EOF
```
> র‍্যান্ডম স্ট্রিং বানাতে: `openssl rand -hex 8`

### ২.৪ পুশ পাবলিশারের পাসওয়ার্ড বদলান — **করে ফেলুন**
`mediamtx.yml`-এ `publishPass: CHANGE_ME_PUBLISH_PASSWORD`। এটা **আসল পাসওয়ার্ড**,
প্লেসহোল্ডার নয় — যেই এটি জানে সে আপনার ভিউয়ারদের দেখানো স্ট্রিম হাইজ্যাক করতে পারে।

```bash
nano mediamtx.yml      # pathDefaults → publishPass: একটা লম্বা র‍্যান্ডম শব্দ
```
একই শব্দটা DVR-এর RTMP সেটিংয়েও দিতে হবে (§২.৬)।

### ২.৫ `mediamtx.yml`-এ পুশ-পাথটা আগেই দেওয়া আছে
repo-তে `dvr-cam-01` নামে একটা entry আছে:
```yaml
  dvr-cam-01:
    source: publisher     # ← MediaMTX কারও পেছনে ছুটবে না, কেউ পুশ করবে
```
**এই নামটাই পরে ক্যামেরার `stream_key` হবে** — হুবহু লিখে রাখুন।
একাধিক চ্যানেল চাইলে:
```yaml
  dvr-cam-01:
    source: publisher
  dvr-cam-02:
    source: publisher
```

### ২.৬ DVR-এ পুশ সেট করুন (ফোনের ব্রাউজারে)
```
Setup → Network → Platform Access → RTMP
```
| ফিল্ড | মান |
|---|---|
| Enable | ✓ |
| Address Type | **Custom** |
| Custom Address | `rtmp://<VPS-IP>:1935/dvr-cam-01` |
| Username | `publisher` |
| Password | §২.৪-এ যেটা দিলেন |

> কিছু ফার্মওয়্যারে address আর stream key আলাদা: তখন address =
> `rtmp://<VPS-IP>:1935/dvr-cam` আর key = `01`। দুটোতেই একই URL দাঁড়ায়।

**সেভ → রিবুট লাগতে পারে।** তারপর যাচাই:

### ২.৭ যাচাই — ৩টা কমান্ড (ফোনের SSH-এ)
```bash
cd ~/AGRO
docker compose -f docker-compose.stream-vps.yml --profile public up -d

# ১) কনটেইনার দুইটা চালু?

# ২) DVR সত্যিই পুশ করছে?  ← এখানে [RTMP] is publishing দেখতে হবে

# ৩) ছবি বের হচ্ছে?  → 200 হলে স্ট্রিম জীবন্ত

```
| ফল | মানে |
|---|---|
| লগে `is publishing` + `200` | ✅ স্ট্রিম এসেছে |
| লগে কিছু নেই | DVR পুশ করছে না — URL/পোর্ট/পাসওয়ার্ড আবার দেখুন |
| `401` | পাসওয়ার্ড ভুল (publishUser/publishPass) |
| `404` | path নাম মেলেনি (`dvr-cam-01` বানান) |

### ২.১০ ট্রাফিকের হিসাব — DigitalOcean-এর কোটা দেখে নিন

## ২খ. 🔍 তিনটা আলাদা IP — কোনটা কোনটা

সবচেয়ে বেশি ভুল এখানেই হয়। আপনার সেটআপে তিনটা আলাদা ঠিকানা আছে, আর
তিনটার কাজও আলাদা:

| IP | কোথায় দেখবেন | এটা কী | ইন্টারনেট থেকে ঢোকা যায়? |
|---|---|---|---|
| `192.168.10.125` | DVR-এর স্ক্রিন/অ্যাপে | **ঘরের LAN ঠিকানা** (RFC 1918) | ❌ কখনোই না |
| `10.x` / `100.64–127.x` / `192.168.x` (WAN) | রাউটারের WAN/Status পেজ | **ক্যারিয়ারের দেওয়া ঠিকানা** | ❌ না (CGNAT হলে) |
| `103.x.x.x` এর মতো | whatismyipaddress.com | **পাবলিক IP** — ইন্টারনেট যা দেখে | ✅ হ্যাঁ |

> ### `192.168.x.x` কেন কখনো পাবলিক নয়
> এটা **প্রাইভেট রেঞ্জ** — RFC 1918। পৃথিবীর প্রত্যেকটা বাড়ি, অফিস,
> দোকান এই একই রেঞ্জ ব্যবহার করে। আপনার বাড়িতে `192.168.10.125`,
> পাশের বাড়িতেও হয়তো `192.168.10.125`।
>
> ভাবুন **বাড়ির রুম নম্বর**ের মতো: "রুম ১২৫" ভেতরে ঠিকানা দেয়,
> কিন্তু ডাকপাটানোর সময় পাড়ার নামটাও লাগে। `192.168.x` = রুম নম্বর,
> পাবলিক IP = পুরো ঠিকানা।
>
> তাই VPS-এ `192.168.10.125` লিখলে সে নিজের ডেটাসেন্টারে
> "১২৫ নম্বর রুম" খুঁজবে — যেটা আপনার বাড়ি নয়।

**পরীক্ষা (২ ধাপ, ফোন থেকেই):**
1. ঘরের WiFi-তে ব্রাউজারে <https://whatismyipaddress.com> → IP টা লিখুন
2. রাউটারে (`http://192.168.10.1`) ঢুকে **WAN / Internet Status** → IP দেখুন

দুইটা **একই** হলে → পাবলিক IP আছে → ফোন লাগবে না।
WAN-এ `10.x`/`100.x`/`192.168.x` থাকলে → CGNAT → ফোন লাগবেই।

## ২ক. ⚡ আগে এই ৫ মিনিটের পরীক্ষা — কোন পথে যাবেন সেটা এটাই ঠিক করে

VPS কেনার **আগে** এটা করে নিন। উত্তরভেদে খরচ আর কাজ সম্পূর্ণ আলাদা।

### ক. পাবলিক IP আছে কি না (ফোন থেকেই)

1. ফোন **মোবাইল ডাটা**-য় (WiFi বন্ধ) ব্রাউজারে যান: <https://whatismyipaddress.com>
   → যে IP দেখাবে সেটা লিখে নিন
2. এবার **ঘরের WiFi**-তে যান, একই সাইটে আবার দেখুন
3. রাউটারের অ্যাডমিন পেজে ঢুকুন (সাধারণত `192.168.1.1`) → **WAN / Internet Status**
   → সেখানে যে IP, সেটাও লিখে নিন

| যা দেখলেন | মানে | কোন পথ |
|---|---|---|
| WAN IP = `10.x` / `100.64–127.x` / `172.16–31.x` / `192.168.x` | **CGNAT** — বাইরে থেকে ঢোকার পথ নেই | §৩.১ (ফোন রিলে) |
| WAN IP = যা whatismyip দেখাচ্ছে (যেমন `103.x.x.x`) | **পাবলিক IP আছে** | নিচের "খ" |

> `100.64.0.0/10` মানে প্রায় সব ক্ষেত্রে CGNAT। বাংলাদেশে অনেক ISP এটাই দেয়।

### খ. পাবলিক IP থাকলে — VPS-কে DVR পর্যন্ত পৌঁছাতে দিন

```bash
# VPS-এ (DVR-এর পাসওয়ার্ড বদলে নিন)
ffmpeg -rtsp_transport tcp -i \
  "rtsp://admin:<DVR-PASS>@<PUBLIC-IP>:554/cam/realmonitor?channel=1&subtype=1" \
  -t 10 -c copy /tmp/test.ts && echo "✅ VPS থেকে DVR দেখা যাচ্ছে"
```

- **`✅` এল** → রাউটারে `554 → DVR-IP:554` ফরওয়ার্ড আছে, আর VPS সরাসরি টানতে পারবে।
  `mediamtx.yml`-এ পথ খ-এর লাইনটা ব্যবহার করুন।
- **`Connection timed out` / `refused`** → ফরওয়ার্ড নেই বা ISP পথ বন্ধ করেছে।
  রাউটারে 554 ফরওয়ার্ড দিন, তারপর আবার। তবু না হলে §৩.১।

> ⚠️ **আপনার DVR-এর IP `192.168.10.125` — এটা ঘরের LAN ঠিকানা।**
> VPS-এর কাছে এই ঠিকানার কোনো মানে নেই (`192.168.x` প্রত্যেক বাড়িতেই থাকে)।
> VPS-এ লিখতে হবে **পাবলিক IP**, আর রাউটারই ভেতরে ঢুকিয়ে দেবে।

### গ. "খ" কাজ না করলে — §৩.১ (ফোন রিলে)

DVR-এর RTSP আছেই, তাই ফোন একটা রিলে হিসেবেই যথেষ্ট। SRJ/RTMP pusher লাগবে না।
বিস্তারিত §৩.১-এ।

## ২গ. 🤔 "VLC-তে তো দেখছি, তাহলে ওয়েবসাইটে কেন নয়?"

এটাই সবচেয়ে স্বাভাবিক প্রশ্ন, আর উত্তরটা এক লাইনে: **VLC আর ব্রাউজার একই
জিনিস নয়।**

| | Android VLC | ব্রাউজার (Chrome/Safari) |
|---|---|---|
| `rtsp://` চালাতে পারে | ✅ হ্যাঁ, হুবহু | ❌ **না**, কখনোই না |
| কোথা থেকে চলছে | আপনার ফোন, **ঘরের WiFi-তে** | ইন্টারনেটে, **যেকোনো জায়গা থেকে** |
| কার কাছে পৌঁছায় | `192.168.10.125` = পাশের ঘর | `192.168.10.125` = অচেনা ঠিকানা |

### দুটো আলাদা বাধা — দুটোই পেরোতে হবে

**বাধা ১ — ফরম্যাট**
ব্রাউজার শুধু **HLS** (`.m3u8`) আর **WebRTC** বোঝে। RTSP বোঝে না, কোনো
এক্সটেনশন দিয়েও না। তাই ছবিটা RTSP → HLS বদলাতে হবে — ওটাই MediaMTX করে।

**বাধা ২ — ঠিকানা**
VLC চলছে আপনার ফোনে, যে **একই WiFi**-তে আছে — তাই সে `192.168.10.125`
পৌঁছাতে পারে। দর্শকদের ব্রাউজার ঢাকায়, চট্টগ্রামে, বা বিদেশে — তাদের কাছে
`192.168.10.125` মানে "আমার নিজের বাড়ির ১২৫ নম্বর রুম"। ভুল জায়গায় খুঁজবে।

```
VLC:      ফোন ──(একই WiFi)──► 192.168.10.125  ✅
ব্রাউজার:  দর্শক ──(ইন্টারনেট)──► 192.168.10.125  ❌ অচেনা
```

> ⚠️ বাধা ২-এর মানে এই যে **RTSP লিংকটা ব্রাউজারে বসালেও কাজ করত না** —
> এমনকি যদি ব্রাউজার RTSP বুঝতও। দুইটা আলাদা সমস্যা, একসাথে সমাধান করতে হবে।

### তাই মাঝখানে একটা সেতু লাগে

```
DVR ──RTSP──► [সেতু] ──HLS──► দর্শকের ব্রাউজার
```

সেতুটা দুটো কাজ একসাথে করে: ফরম্যাট বদলায় **আর** ঠিকানাটা পাবলিক করে।
সেতু কোথায় বসবে — সেটাই আমাদের আগের প্রশ্নগুলোর উত্তর দেয়:

| সেতু | ফরম্যাট বদলায়? | পাবলিক ঠিকানা দেয়? |
|---|---|---|
| VPS (DVR থেকে টানে) | ✅ | ❌ → **পাবলিক IP + ফরওয়ার্ড লাগবে** |
| ফোন রিলে → VPS | ✅ (ব্রাউজারে HLS হয়ে যায়) | ✅ (VPS-এর ঠিকানা) |
| Imou/EZVIZ ক্যামেরা | ✅ (ভেন্ডরই করে) | ✅ |

## ৩. ❌ RTMP নেই — তাহলে তিনটাই বাকি

### ৩.১ 🥇 ফোন/Pi restreamer (CGNAT-এও চলে, খরচ ~৳০)

```
DVR ──RTSP (ঘরের ল্যান)──► পুরোনো ফোন/Pi ──SRT push (বাইরে)──► VPS ──► দর্শক
```
কেন চলে: push আবার বাইরের দিকে — CGNAT বাধা দেয় না।
কেন সবসময় ভালো নয়: **ক্যামেরা সাইটে ২৪/৭ একটা ডিভাইস বাঁচিয়ে রাখতে হবে**।
বিদ্যুৎ/ইন্টারনেট গেলে ছবি যাবে। ১০ W × ২৪/৭ ≈ **৳৬৫/মাস** বিদ্যুৎ।

**সেটআপ (ফোন থেকে করা যায়):**
1. পুরোনো Android ফোনে **Termux** (F-Droid থেকে) ইনস্টল — Play Store-এর ভার্সনটা পুরোনো
2. VPS-এ SRT পোর্ট খুলুন — `docker-compose.stream-vps.yml`-এ `# - "8890:8890/udp"`
   কমেন্ট খুলে দিন, আর DigitalOcean Firewall-এ **UDP 8890**
3. `mediamtx.yml`-এ পথটা আগেই আছে: `dvr-cam-01` (`source: publisher`)।
   SRT আর RTMP একই path-এ পাবলিশ হয়, তাই নতুন কিছু লিখতে হবে না।
4. ফোনে (আপনার DVR-এর **LAN** IP আর পাসওয়ার্ড বসান):
```bash
pkg install ffmpeg -y
termux-wake-lock
ffmpeg -rtsp_transport tcp \
  -i "rtsp://admin:<DVR-PASS>@192.168.10.125:554/cam/realmonitor?channel=1&subtype=1" \
  -c copy -f mpegts \
  "srt://<VPS-IP>:8890?streamid=publish:dvr-cam-01&passphrase=<MEDIAMTX_PUBLISH_PASS>"
```
> `passphrase` = `.env`-এর `MEDIAMTX_PUBLISH_PASS`। কোট (`<…>`) বাদ দিয়ে শুধু শব্দটা বসান।
> `subtype=1` সাবস্ট্রিম — ৫১২ kbps, ব্যান্ডউইথ বাঁচে। `subtype=0` পুরো রেজোলিউশন।
5. ফোনে চার্জার লাগিয়ে রাখুন, WiFi কখনো বন্ধ করবেন না
6. ২৪/৭ চালু রাখতে Termux-এ `sv`/`nohup` দিয়ে স্ক্রিপ্ট রাখুন, ব্যাটারি অপটিমাইজেশন থেকে
   Termux-কে ছাড় দিন (Settings → Apps → Termux → Battery → Unrestricted)

> এতে ট্রান্সকোডিং নেই (`-c copy`) — পুরোনো ফোনেও CPU লাগে না।
> DVR-এর সাবস্ট্রিম **H.264** হতে হবে (H.265 হলে ব্রাউজারে চলবে না)।

### ৩.২ 🥈 ISP থেকে পাবলিক IP

CGNAT-এর একমাত্র আসল সমাধান ISP-র হাতে। কল/মেসেজ:

> আসসালামু আলাইকুম। আমার কানেকশনে WAN IP `10.x.x.x` (private) আসছে,
> মানে আমি CGNAT-এর পিছনে। CCTV বাইরে থেকে দেখতে **real public IPv4** দরকার।
> PPPoE কানেকশনে এটা দেওয়া সম্ভব কি? চার্জ কত?

পেলে: রাউটারে `554 → DVR-IP:554` ফরওয়ার্ড → `mediamtx.yml`-এ
`source: rtsp://admin:<pass>@<পাবলিক-IP>:554/cam/realmonitor?channel=1&subtype=1`
→ VPS নিজেই টানবে। **কিন্তু তখন VPS-টা কেন?** — কারণ ব্রাউজার RTSP চালাতে
পারে না; RTSP→HLS বদলাতে মাঝখানে MediaMTX লাগবেই।

> ⚠️ "পোর্ট খুলে দিন" বলবেন না — ISP রাউটারে ঢুকবে না। শুধু **public IP** চাইবেন।

### ৩.৩ 🥉 ক্যামেরা বদলানো (Imou)

Dahua DVR-এর বদলে **Imou** ক্যামেরা নিলে ক্লাউড পথ খোলে (`cloud_provider = imou`) —
VPS, পাবলিক IP, ফোন-বক্স কিছুই লাগে না। কিন্তু **প্রতি দর্শক-ঘণ্টায়** Imou-র
ট্রাফিক বিল ($0.25/GB) — ১০ জন ২৪/৭ = ~৳৫০,০০০/মাস। শুধু মাঝেমধ্যে দেখার জন্য ঠিক।

> আপনার DVR + ক্যামেরা **আগেই আছে** — তাই ৩.১ সবচেয়ে বাস্তব। টাকা খরচ হবে শুধু VPS-এ।

## ৩ক. 🚀 সবচেয়ে সহজ পথ — একটাই ফোন, ভিপিএস-এ দুইটা কমান্ড

উপরের §৩.১ একই কাজ করে, কিন্তু এখানে কম কমান্ড আর কম ফাঁদ।

**ফোনে (Termux):**
```bash
pkg install ffmpeg -y
termux-wake-lock
ffmpeg -rtsp_transport tcp \
  -i "rtsp://admin:<DVR-PASS>@192.168.10.125:554/cam/realmonitor?channel=1&subtype=1" \
  -c copy -f mpegts \
  "rtmp://<VPS-IP>:1935/dvr-cam-01"
```

> **পাসওয়ার্ড কেন নেই এখানে?** RTMP-তে লেখা যায় না, তাই MediaMTX-এর
> `internal` auth-এ `dvr-cam-01` পাথটা গোপন রাখাই নিরাপত্তা। এজন্যই
> path বসিয়ে লম্বা রাখা হয়েছে — কেউ URL আন্দাজ করতে পারবে না।
> আরও শক্ত চাইলে SRT ব্যবহার করুন (§৩.১) — সেটায় passphrase আছে।

**VPS-এ:**
```bash
git clone https://github.com/farukhossain25/AGRO && cd AGRO
cp .env.example .env && nano .env      # MEDIAMTX_PUBLISH_PASS + MEDIAMTX_READ_PASS দিন
docker compose -f docker-compose.stream-vps.yml up -d mediamtx
```

> `docker compose` **শুধু mediamtx** — `--profile public` দিলে Caddy 80/443
> দখল করবে আর `STREAM_PUBLIC_HOST` চাইবে। প্রথমে ভিডিওটা দেখা, পরে এজ।

**দেখা যাচ্ছে কি না — একই VPS-এ:**

## ৩খ. 📱 ফোনটা সত্যিই ২৪/৭ চালু রাখতে হবে?

**হ্যাঁ — তবে সেটা কারণটা বোঝা জরুরি।** ফোনটা "নজরদারি" করছে না, ওটা
**সেতু**: DVR-এর ছবি বাইরে পৌঁছানোর একমাত্র রাস্তা। সেতু বন্ধ = ছবি বন্ধ।

### ২৪/৭ না রাখলে কী হয়

| ফোন বন্ধ থাকলে | কী হয় |
|---|---|
| দর্শক সাইটে ঢোকে | "ক্যামেরা অফলাইন" দেখে (সাইট ভাঙে না) |
| VPS | ঠিকই চলে, শুধু কোনো স্ট্রিম পায় না |
| DVR `rtsp://` | চালুই থাকে — VLC দিয়ে ঘরের ভেতরে দেখা যাবে |

### কেন DVR নিজে পাঠাতে পারছে না

| পথ | কেন হবে না |
|---|---|
| DVR → ভিপিএস (RTMP) | আপনার মডেলে **RTMP নেই** |
| DVR → কোনো ক্লাউড | Dahua P2P-তে থার্ড-পার্টি API নেই |
| **ভিপিএস → DVR (pull)** | চাই **পাবলিক IP + রাউটারে 554 ফরওয়ার্ড** |

➡️ **তৃতীয়টা করে ফেলতে পারলে ফোনের দরকারই নেই।** VPS নিজেই টানবে, ২৪/৭,
কোনো ডিভাইসের উপর নির্ভরতা ছাড়া।

### তাই প্রশ্নটা উল্টো করুন: পাবলিক IP আছে?

**রাউটারের অ্যাডমিন পেজ খুলুন** (`http://192.168.1.1` বা `http://192.168.10.1`)
→ **WAN / Internet / Status** → IP টা দেখুন

| WAN IP | মানে | রায় |
|---|---|---|
| `10.x`, `172.16–31.x`, `192.168.x` | **CGNAT** — বাইরে থেকে ঢোকা যায় না | **ফোন লাগবেই** |
| `100.64.x` – `100.127.x` | **CGNAT** (ক্যারিয়ার-গ্রেড NAT) | **ফোন লাগবেই** |
| অন্য যেকোনো (`103.x`, `202.x`…) | **পাবলিক IP আছে** | **ফোন লাগবে না** 🎉 |

> এই একটা IP দেখে নেওয়া সবচেয়ে দামি কাজ — বিনামূল্যে, আর উত্তরটা
> পাকাপাকি। ফোন কেনা/সাজানোর আগে এটা করুন।

### তৃতীয় পথ: রাউটারই রিলে (আগে ভাবিনি, কিন্তু সম্ভব)

আপনার রাউটার যদি **OpenWrt / Padavan / Asus Merlin** চলে, ওটা নিজেই
`ffmpeg` চালাতে পারে — তখন ফোনের বদলে **রাউটারই ২৪/৭ সেতু**।
বিদ্যুৎ যায়নি কিন্তু ফোনের চার্জার খুলে ফেলেছেন — এমন কিছু আর হবে না।
শর্ত: রাউটারে ffmpeg ইনস্টল করা যায়, আর র‍্যাম ≥ ১২৮ MB।
স্টক ISP-রাউটারে সাধারণত যায় না।

### ফোন কি ২৪/৭ **টিকবে**?

| সমস্যা | সমাধান |
|---|---|
| ফোন ঘুমিয়ে পড়ে | Termux → `termux-wake-lock` (আগেই দিয়েছি) |
| Android ব্যাকগ্রাউন্ডে মারে | Settings → Apps → Termux → Battery → **Unrestricted** |
| ব্যাটারি ফুলে যায় | **পুরোনো ফোন** ব্যবহার করুন, নতুন নয়। চার্জার লাগিয়ে রাখলে ব্যাটারি গরম হয় — ভালো মানের চার্জার, খোলা জায়গায় রাখুন |
| WiFi বন্ধ হয়ে যায় | রাউটারে Termux-এর MAC-এ **static DHCP** দিন |
| বিদ্যুৎ যায় | ছোট UPS (৳২–৩ হাজার) — ফোন + রাউটার দুইটাই চলবে |
| ইন্টারনেট যায় | কোনো সমাধান নেই; VPS-এ "অফলাইন" দেখাবে |

> ⚠️ লিথিয়াম ব্যাটারি ২৪/৭ চার্জে থাকলে ফোলার ঝুঁকি থাকে। **দীর্ঘমেয়াদে
> Raspberry Pi বা মিনি-PC (৳৫–৮ হাজার, ৩–৫ W)** ফোনের চেয়ে নিরাপদ
> আর বেশি টেকসই — একবার কিনলেই চলবে বছরের পর বছর।
