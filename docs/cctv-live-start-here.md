# CCTV লাইভ — এখান থেকে শুরু করুন (এক পেজের চেকলিস্ট)

**এই ডকে যা আছে:** Imou ক্যামেরা কিনে আপনার ওয়েবঅ্যাপে লাইভ দেখাতে ঠিক কী কী করতে হবে —
ক্রম অনুযায়ী, কোনটা আগে, কোনটা পরে। আর কোথায় কোড বদলাতে হবে (প্রায় কোথাও না)।

> ### 🔀 আপনার হাতে Dahua XVR আগেই আছে?
> তাহলে **`live-camera-xvr-imou.md` → §৭** পড়ুন। সারমর্ম:
>
> 1. XVR-এ RTMP নেই — **RTSP-ই একমাত্র আউটপুট**।
>    `rtsp://USER:PASS@HOST:554/cam/realmonitor?channel=N&subtype=1`
> 2. CGNAT-এর পেছনে থাকলেও সমস্যা নেই: খামারের রাউটারে **WireGuard** চালান,
>    VPS টানেলের ভেতর থেকে XVR-কে RTSP দিয়ে টানবে। পোর্ট ফরওয়ার্ড লাগে না।
> 3. সাব-স্ট্রিম **H.264** করুন (ব্রাউজার H.265 চালায় না)।
>
> পুরোনো `live-camera-dahua-digitalocean.md`-এর RTMP ভিত্তিক পরামর্শ এই
> ডিভাইসে প্রযোজ্য নয়।

**রেকর্ডিং কোথাও নেই** — `mediamtx.yml`-এ `record: false`। শুধু লাইভ।

## ১. 🔴 ধাপ ০ — ১০ মিনিটের ফ্রি টেস্ট (ক্যামেরা কেনার আগেই)

**লক্ষ্য:** ফার্মের ক্যামেরা ইন্টারনেট থেকে সরাসরি দেখা যায় কি না — সেটা জানা।
**যা লাগবে:** ফোন (WiFi + মোবাইল ডাটা), VLC অ্যাপ, Dahua XVR-এর পাসওয়ার্ড, XVR-এর IP।
**খরচ:** ৳০।

### ১.১ নেটওয়ার্কের তথ্য বের করুন (ফোনেই)

XVR-তে স্ক্রিন নেই, তাই DMSS অ্যাপ বা রাউটার থেকেই তথ্য নিতে হবে:

**ক) XVR-এর IP**
- রাউটারের অ্যাডমিন প্যানেল (ব্রাউজারে `192.168.0.1` বা `192.168.1.1`) → DHCP Client List
- সেখানে `Dahua` বা MAC অ্যাড্রেস দেখে IP নিন — যেমন `192.168.0.108`
- বা DMSS → ডিভাইস → সেটিংস → ডিভাইস ইনফো → IP

**খ) XVR-এর পাসওয়ার্ড**
এই ৩টার একটা হবে (পুরোনো Dahua-র সাধারণ ডিফল্ট):
```
admin / admin
admin / 123456
admin / নিজের সেট করা পাসওয়ার্ড
```
> পুরোনো Dahua ওয়েব ইন্টারফেসে `admin/admin` চলে। না হলে DMSS-এ যেই পাসওয়ার্ড দিয়ে লগইন করেন, সেটাই।

**গ) DHCP-তে IP বেঁধে দিন**
রাউটারের DHCP সেটিংসে XVR-এর MAC-কে fixed/reserved IP দিন। নাহলে রিবুটে IP বদলে গেলে কনফিগ ভাঙবে।

### ১.২ VLC ইনস্টল করুন

- Play Store → **VLC for Android** (VideoLAN) → ইনস্টল
- ইন্টারনেট ছাড়া চলে, বিজ্ঞাপন নেই

### ১.৩ প্রথম টেস্ট — ঘরের WiFi দিয়ে (ভেতরের নেটওয়ার্ক)

**এটা এখনো কোনো প্রমাণ না**, শুধু নিশ্চিত হওয়া যে লিংক আর পাসওয়ার্ড ঠিক আছে।

1. **WiFi চালু** রাখুন
2. VLC → বাম মেনু → **Stream** → `New stream`
3. এই লিংক দিন (IP আর পাসওয়ার্ড বদলে):
   ```
   rtsp://admin:admin@192.168.0.108:554/cam/realmonitor?channel=1&subtype=1
   ```
4. **ছবি এলে** → লিংক ঠিক ✅ → এখন আসল টেস্টে যান
5. **না এলে** → পাসওয়ার্ড/IP ভুল, অথবা RTSP বন্ধ। **এখানেই থামুন**, ঠিক করে আবার

> `channel=1` = Dahua-তে ১ নম্বর চ্যানেল · `subtype=1` = সাব-স্ট্রিম (হালকা)
> ছবি এলে `subtype=0` দিয়ে HD-ও টেস্ট করতে পারেন — পরে মোবাইল ডাটায় ভারী লাগবে

### ১.৪ আসল টেস্ট — মোবাইল ডাটা দিয়ে (এটাই নির্ণায়ক)

**⚠️ WiFi সম্পূর্ণ বন্ধ করুন** — শুধু "WiFi অফ, মোবাইল ডাটা অন" দেখলে হবে না,
ফোনের **WiFi আইকনটাই বন্ধ** করুন। দুইটা একসাথে চালু থাকলে ফোন WiFi-ই ব্যবহার করে,
আর টেস্টটা মিথ্যা "পাস" দেখাবে।

1. WiFi বন্ধ → মোবাইল ডাটা (4G/5G) চালু — ব্রাউজারে গুগল খুলে দেখুন নেট আছে
2. এয়ারপ্লেন মোড চালু করে আবার বন্ধ করলে নেটওয়ার্ক রিফ্রেশ হয় (ঐচ্ছিক)
3. VLC → Stream → **একই লিংক** (ঘরের `192.168.0.108` — এটা এখনো)
4. ১৫–২০ সেকেন্ড অপেক্ষা করুন

| ফল | মানে |
|---|---|
| ❌ **ছবি আসে না** (স্বাভাবিক) | `192.168.x.x` ইন্টারনেট থেকে দেখা যায় না — এটা **প্রত্যাশিত** |
| ✅ ছবি আসে | আশ্চর্য — আপনার ISP হয়তো সরাসরি পাবলিক রুট দিচ্ছে |

> **এই টেস্টটা ফেল করবেই** — কারণ `192.168.x.x` হলো ঘরের ভেতরের ঠিকানা।
> ফেল করাটা খারাপ খবর নয়। আসল প্রশ্ন পরের ধাপে।

### ১.৫ আসল প্রশ্ন — আপনার ISP কি public IP দিয়েছে?

এটাই একমাত্র নির্ণায়ক টেস্ট। ৩ ভাবে করা যায়:

**উপায় ক — রাউটারের WAN IP (সবচেয়ে সহজ)**
1. রাউটার অ্যাডমিন → **Status / WAN** পেজ → WAN IP দেখুন
2. ব্রাউজারে <https://ipinfo.io> → ইন্টারনেটের দিকের IP দেখুন
3. তুলনা করুন

| রাউটারের WAN IP | মানে | পথ |
|---|---|---|
| **`192.168.x.x` / `10.x.x.x` / `172.16–31.x.x`** | 🚫 **private IP** — রাউটার নিজেই NAT করছে, ISP-র কাছে যাওয়ার পথেই বেসরকারি ঠিকানা | **পথ খ** (পথ ক'তে কিছু নেই) |
| **`100.64.x.x` – `100.127.x.x`** | 🚫 **CGNAT** — ISP-র নিজের বেসরকারি নেটওয়ার্ক (এই রেঞ্জটা ঠিক এ কাজের জন্যই সংরক্ষিত) | **পথ খ** |
| **অন্য যেকোনো** (`103.x`, `45.x`, `1.x`…) | ✅ public IP | **পথ ক** |

> **"private IP বলছে" মানে কী?**
> - **WAN পেজে `192.168.x.x`** → আপনার রাউটার হয় দ্বিতীয় রাউটারের পিছনে (ডাবল NAT), নয়তো
>   ISP-র দেওয়া ONT/মডেম রাউটার মোডে চলছে। এখানে **আপনার রাউটারে port forward করলে
>   কোনো লাভ নেই** — আগে ওই উপরের ডিভাইসে করতে হবে।
> - **`ipinfo.io` যা দেখাচ্ছে সেটাও private** → এটা সাধারণত ব্রাউজার/নেটওয়ার্কের ক্যাশ, নয়তো
>   আপনি VPN-এ আছেন। একবার মোবাইল ডাটা দিয়ে দেখুন।
>
> দুটোর যেটাই হোক, ফল একই: **বাইরে থেকে ঢোকার পথ নেই** → পথ খ।

**private IP হলে করণীয় (দুটো আলাদা সমস্যা, দুটো আলাদা সমাধান):**

| অবস্থা | সমাধান |
|---|---|
| **ডাবল NAT** (আপনার রাউটার ISP-র ONT-এর পিছনে) | ISP-র ONT-তে **bridge mode** চালু করুন বা ISP-কে বলুন — তারপর আপনার রাউটার নিজেই public IP পাবে |
| **আসল CGNAT** (ONT/WAN-ও `100.64.x.x`) | শুধু ISP পারবে — real public IP-র আবেদন, নয়তো পথ খ |

> 📞 ISP-কে ঠিক এভাবে বলুন: *"আমার WAN IP 192.168/100.64 সিরিজে আছে, মানে আমি NAT-এর
> পিছনে। CCTV বাইরে থেকে দেখতে চাই — real public IPv4 দরকার, ফ্রি হয় কি?"*

**উপায় খ — traceroute (মোবাইল থেকেও হয়)**
Android-এ **Termux** বা যেকোনো "Traceroute" অ্যাপ → `8.8.8.8`
- প্রথম ২–৩ হপে `100.64.x.x` / `10.x.x.x` / `172.16–31.x.x` দেখলে → **CGNAT**
- প্রথম হপই পাবলিক IP হলে → public IP আছে

**উপায় গ — ISP-কে জিজ্ঞেস**
কল/মেসেজ: *"আমার কানেকশনে কি real public IPv4 আছে? CCTV বাইরে থেকে দেখতে চাই।"*
এটাই সবচেয়ে নিশ্চিত উত্তর — কারণ কখনো রাউটার IP দেখে বোঝা যায় না।

### ১.৫ক 🔴 নিশ্চিত ফলাফল (রাউটার স্ক্রিনশট থেকে): **CGNAT**

```
WAN IP        : 10.30.17.237        ← private (RFC1918)
Default Gateway: 10.30.17.237       ← একই ঠিকানা
Subnet Mask   : 255.255.255.255     ← /32 পয়েন্ট-টু-পয়েন্ট
Connection    : PPPoE
```

**তিনটাই একসাথে CGNAT-এর প্রমাণ:**

| প্রমাণ | মানে |
|---|---|
| WAN IP `10.x.x.x` | বেসরকারি ঠিকানা — ইন্টারনেটে রুট হয় না |
| Gateway = WAN IP, mask `/32` | ISP-র রাউটারের সাথে শুধু একটা পয়েন্ট-টু-পয়েন্ট লিংক |
| Public IP আলাদা (`118.179.28.120`) | ওই ঠিকানাটা ISP-র NAT পুলের, আপনার নয় |

👉 **আগের পোর্ট-৮০ "Success" ছিল ভুয়া পজিটিভ** — `118.179.28.120:80`-এ
যে সাড়া দিয়েছিল সেটা আপনার রাউটার নয়, ISP-র শেয়ার্ড NAT-এর পিছনের অন্য কিছু
(বা ISP-র নিজের সার্ভিস)। CGNAT-এ বাইরে থেকে ভেতরে ঢোকার পথই নেই।

**ফল: পথ ক এখনই অসম্ভব। VPS কিনবেন না — ওটা ক্যামেরা পর্যন্ত পৌঁছাবে না।**

### ১.৫খ ISP-কে ঠিক এটা পাঠান

> আসসালামু আলাইকুম। আমার কানেকশনে WAN IP `10.30.17.237` (private) আসছে,
> মানে আমি CGNAT-এর পিছনে। আমার CCTV ক্যামেরা ইন্টারনেট থেকে দেখতে **real
> public IPv4** দরকার। PPPoE কানেকশনে এটা দেওয়া সম্ভব কি? চার্জ কত?
> দরকার হলে static IP দিলেও চলবে।

**সম্ভাবনা:** বাংলাদেশে অনেক ISP (DFN, Carnival, некоторые lokal ISP) অনুরোধে
ফ্রি public IP দেয়; কেউ ৳৩০০–১,২০০/মাস নেয়। PPPoE হলে দেওয়া সহজ।

**⚠️ যা বলবেন না:** "পোর্ট খুলে দিন" — ওরা রাউটারে ঢুকে কিছু করবে না।
শুধু **public IP** চাইতে হবে, port forward আপনি করবেন।

**❌ যা করলে সময় নষ্ট:** ONT-তে bridge mode — এখানে ONT আলাদা ডিভাইসই নেই,
রাউটার নিজেই CGNAT-এ। ডাবল NAT নয়, ISP-লেভেল NAT।

### ধাপ ১ — রাউটারে পোর্ট খুলুন ⚠️ এখানেই বেশিরভাগ মানুষ আটকায়

1. রাউটারের অ্যাডমিন প্যানেল → **Port Forwarding / Virtual Server**
2. নিয়ম: `External 554 → Internal 192.168.0.108:554` (TCP) — বা সোর্স কোডের ভাষায়
   `subtype=1` দিলে শুধু 554 দরকার, RTSP-ই যথেষ্ট
3. **554 ব্লক থাকলে** বাইরের পোর্ট `1554` দিয়ে ম্যাপ করুন, URL-এ `:1554` দিন

**🧪 বাইরে থেকে পোর্ট খোলা কি না — ক্যামেরা কেনার আগেই টেস্ট করুন:**

⚠️ **টেস্টের আগে ফরওয়ার্ড করতেই হবে।** ফরওয়ার্ড না করে চেক করলে টুল যা-ই বলুক,
সেটা অর্থহীন — ৫৫৪ পোর্টে কিছু শোনারই নেই।

- ফোনের **মোবাইল ডাটা** দিয়ে (WiFi বন্ধ) ব্রাউজারে <https://canyouseeme.org>
- **Port: `554`** ← সব সময় ক্যামেরার পোর্ট দিয়ে চেক, ডিফল্ট `80` নয়
- Check → **"Success"** এলে পোর্ট খোলা ✅
- "Connection refused/timed out" → হয় ফরওয়ার্ড ভুল, নয়তো ISP ব্লক করেছে

> ### 🔍 স্ক্রিনশট থেকে যা বুঝলাম (IP `118.179.28.120`, পোর্ট 80 = Success)
>
> **ভালো খবর:** `118.179.28.120` একটা **public IP** — `100.64–100.127` বা
> `192.168/10.x` নয়। মানে ISP NAT-এর পিছনে নেই।
> **কিন্তু এটা এখনো প্রমাণ নয়** — পোর্ট 80 আপনার রাউটারের নিজের পেজও হতে পারে,
> আর ৫৫৪ একদম অন্য পোর্ট।
>
> **তিনটা জিনিস নিশ্চিত করুন:**
> 1. পোর্ট ৮০ খোলা রাখার দরকার নেই — বন্ধ করুন, শুধু ৫৫৪ (পরে VPS-এর জন্য 80/443)
> 2. রাউটার → WAN পেজের IP = **ঠিক `118.179.28.120`** কি না দেখুন। আলাদা হলে
>    আপনার ISP-র ONT-এর পিছনে আছেন (ডাবল NAT) — ONT-তেও ফরওয়ার্ড লাগবে
> 3. **`554` দিয়ে আবার চেক করুন** — এটাই আসল প্রশ্ন

**👍 পোর্ট ৮০-তে Success কেন ভালো ইঙ্গিত:** আগে ঠিক করা চেকটা হলো ISP-র
ফিল্টার। ISP যদি ইনবাউন্ডেই সব ব্লক করে, ৮০-ও ফেল করত। ৮০ পাস করা মানে
**ISP সাধারণভাবে ব্লক করছে না** — শুধু ৫৫৪ আলাদা করে টেস্ট করা বাকি।

> ⚠️ **IPv4 vs IPv6:** ISP যদি শুধু IPv6 দেয়, port forward IPv4-এ কাজ করবে না।
> `canyouseeme.org` আগে IPv4 টেস্ট করে — সেখানে ফেল করলে ISP-কে জিজ্ঞেস করুন।

**📌 DDNS বাধ্যতামূলক নয়, তবে ভালো:** public IP সাধারণত মাসে ২–৩ বার বদলায়।
No-IP বা DuckDNS-এ ফ্রি হোস্টনেম নিন (যেমন `farm-bishwas.ddns.net`), রাউটারে DDNS
সেট করুন, আর `mediamtx.yml`-এ IP-র বদলে হোস্টনেম দিন। IP বদলালেও কনফিগ ভাঙবে না।

**📌 ক্যামেরা H.264-এ সেট করুন:** Imou Life → অ্যাডভান্সড → ভিডিও এনকোডিং →
**H.264** (H.265 নয়)। H.265 ব্রাউজারের HLS-এ চলে না — ছবি আসবেই না।

## ৪.৫ ❓ "Public IP ছাড়া VPS দিয়ে হবে না?" — না, হবে না। কারণটা পরিষ্কার করে বলি

**VPS থাকলেও VPS ক্যামেরা পর্যন্ত পৌঁছাতে পারবে না।**

```
ক্যামেরা (192.168.0.108)   ← ISP-র NAT-এর ভেতরে
        ▲
        │  এই তীরটা কারও পক্ষে আঁকা সম্ভব নয়
   ISP-র NAT  ────────  10.30.17.237  (আপনার WAN, private)
        ▲
        │  "ক্যামেরা দেখতে চাই" → অনুরোধ বাইরে যেতে পারে
   আপনার VPS ──✗──►  কিন্তু ভেতরে ঢোকার পথ নেই
```

VPS একটা কম্পিউটার। সে ক্যামেরার ঠিকানা জানে না, আর ISP ওই ঠিকানায় ঢুকতেই দেয় না।
তাই VPS-এর কাজ (RTSP→HLS কনভার্ট) করার জন্য **যে ভিডিওটা কনভার্ট করতে হবে, সেটাই পৌঁছায় না**।

### ⭐ একমাত্র পথ যা CGNAT-এ কাজ করে — ক্যামেরা নিজেই বেরিয়ে যায়

```
ক্যামেরা ──(নিজে থেকেই বাইরে যায়)──► Imou ক্লাউড CDN ──► আমাদের সার্ভার ──► ব্রাউজার
```

CGNAT শুধু **বাইরে থেকে ভেতরে** ঢুকতে দেয় না। **ভেতর থেকে বাইরে** যেতে কোনো বাধা নেই।
Imou ক্যামেরা নিজেই ক্লাউডে সংযোগ ধরে রাখে — তাই কোনো inbound পোর্ট, public IP,
VPS কিছুই লাগে না। **Imou Life অ্যাপ ঠিক এভাবেই কাজ করছে**, আর আমরা একই ক্লাউড API
ব্যবহার করি (`cloud_provider = imou`)।

### `IPC-K3DP-3H0WF`-এ এটা চলবে?

| প্রশ্ন | উত্তর |
|---|---|
| RTSP আছে? | ✅ হ্যাঁ (৫৫৪) |
| ONVIF আছে? | ✅ হ্যাঁ |
| **Imou ক্লাউড API এই রিভিশনে টেস্টেড?** | ⚠️ **না** — `IPC-K3DP-3H0WF` কমিউনিটি টেস্ট-টেবিলে নেই (`IPC-F42F-D` আছে) |
| তাহলে | Imou Life-এ লাইভ দেখা গেলেই বোঝা যাবে ক্যামেরা ঠিক আছে; সাইটে দেখানোটা **ফেরত দেওয়ার ২৪ ঘণ্টার ভেতরে** টেস্ট করুন |

> ⚠️ **সৎ সতর্কতা:** এই মডেলের ক্লাউড API সমর্থন **অনুমান, গ্যারান্টি নয়**। রিটার্ন
> সুবিধা থাকলে কিনে টেস্ট করুন, কাজ না করলে ফেরত দিন। ১০০% নিশ্চিত কিছু চাইলে
> **`IPC-F42F-D`** খুঁজুন — সেটা টেস্টেড।

### তাহলে VPS-টা কী হবে?

| অবস্থা | VPS |
|---|---|
| CGNAT + Imou ক্লাউড (এখন) | ❌ **লাগবে না** — ভিডিও Imou CDN থেকে আসে |
| public IP পেলে (পরে) | ✅ লাগবে — Contabo/Oracle, তখনই কিনবেন |

## ৪.৬ 🏡 একাধিক খামার — কতগুলো public IP লাগবে?

**সংক্ষেপে: ক্যামেরার সংখ্যা দিয়ে নয়, *ইন্টারনেট লাইনের* সংখ্যা দিয়ে গোনা হয়।**

### নিয়ম

| প্রশ্ন | উত্তর |
|---|---|
| ১টা খামারে ৮টা ক্যামেরা? | **১টা public IP** — সব ক্যামেরা একই লাইনে |
| ৩টা আলাদা জায়গায় ৩টা লাইন? | **৩টা public IP** (প্রতি লাইনে ১টা) |
| একই বাড়িতে ২টা খামার, ১টা রাউটার? | **১টা public IP** |
| ৪G রাউটার / মোবাইল ডেটা? | **০টা** — সবসময় CGNAT, public IP পাওয়া যায় না |
| Imou ক্লাউড পথ (পথ খ)? | **০টা** — কোনো লাইনে কিছু লাগে না |

### ১টা IP-তে অনেক ক্যামেরা কীভাবে?

**উপায় ১ — আলাদা পোর্ট (আলাদা IP ক্যামেরা):**
```
External 1554 → 192.168.0.108:554   (ক্যামেরা ১)
External 2554 → 192.168.0.109:554   (ক্যামেরা ২)
External 3554 → 192.168.0.110:554   (ক্যামেরা ৩)
```

**উপায় ২ — DVR/XVR হলে ১টা পোর্টই যথেষ্ট (সবচেয়ে সস্তা):**
```
External 1554 → 192.168.0.108:554   ← শুধু একটাই ফরওয়ার্ড
তারপর channel=1, 2, 3 … 16
```
Dahua/Imou DVR-এর ৮–১৬ চ্যানেল একটাই পোর্টে চলে (`?channel=2`, `?channel=3`…)।
**খামারে পুরোনো DVR থাকলে এটা সবচেয়ে ভালো** — ১টা ফরওয়ার্ডে ১৬টা ক্যামেরা।

### 🌟 বড় সুবিধা যেটা অনেকে জানে না

VPS ক্যামেরা থেকে **একবার** টানে, তারপর সব দর্শককে ভাগ করে দেয়:

```
ক্যামেরা ──০.৫ Mbps──► VPS ──০.৫ Mbps × ৫০ জন──► ৫০ দর্শক
```

**৫০ জন দেখলেও খামারের আপলোড ০.৫ Mbps-ই থাকে** — শুধু VPS-এর আউটবাউন্ড বাড়ে।
তাই খামারের ইন্টারনেট লাইনের গতি দর্শকের সংখ্যার সাথে কোনো সম্পর্ক রাখে না। ✅

### ⛔ আর একটা কথা — Public IP ছাড়া কী হবে?

| খামারের অবস্থা | কী করবেন |
|---|---|
| ব্রডব্যান্ড + public IP পেয়েছেন | ✅ RTSP + VPS (`cloud_provider = none`) |
| ব্রডব্যান্ড কিন্তু CGNAT | Imou ক্লাউড (`cloud_provider = imou`) |
| **মোবাইল/৪G রাউটার** | Imou ক্লাউড — কখনোই public IP পাবেন না |
| গ্রামে লাইনই নেই | Imou ক্লাউড + ৪G রাউটার |

### 💡 কোডে মিশিয়ে চালানো যায় — এটাই আসল সুবিধা

`cameras.cloud_provider` **প্রতি ক্যামেরায় আলাদা** সেট হয়। তাই:

| খামার | সোর্স | কেন |
|---|---|---|
| সাভার (public IP আছে) | `none` → VPS | খরচ প্রায় ৳০, ২৪/৭ সম্ভব |
| গাজীপুর (CGNAT) | `imou` → ক্লাউড | IP নেই, কাজ চলবে |
| টাঙ্গাইল (৪G) | `imou` → ক্লাউড | IP পাওয়ার উপায় নেই |

**এক সাইটে দুই পদ্ধতি একসাথে চলবে** — `farm-cameras.tsx` ক্যামেরা দেখে নিজেই
সঠিক প্লেয়ার বেছে নেয় (`CloudPlayer` নাকি `LiveStreamLazy`)। **কোড চেঞ্জ লাগবে না।**

### তাহলে আপনার জন্য বাস্তব পরামর্শ

1. **প্রথমে ১টা খামার** — Imou ক্যামেরা ১টা দিয়ে শুরু, পথ খ (ক্লাউড)
2. **সেই খামারেই ISP-কে public IP-র আবেদন** — পেলে Contabo + RTSP, খরচ নামবে
3. নতুন খামার যোগ হলে **প্রতিটা লাইনে আলাদা করে** ISP-র সাথে কথা বলবেন
4. যে খামারে public IP নেই — সেটা `imou`-তেই থাকবে, কিছুই ভাঙবে না

> **একটা VPS-ই সব খামারের জন্য যথেষ্ট** — প্রতি খামারে আলাদা VPS লাগবে না।
> ১০টা খামারের ১০টা ক্যামেরাও একই MediaMTX থেকে চলবে (২ OCPU-তে ~২০টা স্ট্রিম)।

## ৪.৭ 💰 Imou-র storage/ক্লাউড দিয়ে ৫,০০০+ ইউজার — মাসিক কত?

> Imou-র ক্লাউড **ভিডিও ট্রাফিক (flow)**-এ বিল করে: ফ্রি ২ GB/মাস, তারপর
> **$0.25/GB**। প্রতি দর্শক-ঘণ্টা ৫১২ kbps-এ = **০.২৩ GB = ৳২৮**।

|---|---|---|---|---|
| ২ মিনিট | ৫,০০০ | ১,১৫২ GB | **৳৩৫,০৭৫** | ৳০ (Oracle) |

## ৪.৮ 🔁 public IP একবার পেলে — সারা জীবন চলবে?

**সংক্ষেপে: পাবেন "static" নাকি "dynamic" — সেটাই আসল প্রশ্ন।**

| ধরন | কী হয় | সারাজীবন? |
|---|---|---|
| **Dynamic public IP** (বেশিরভাগ ISP) | IP মাঝে মাঝে বদলায় (রাউটার রিবুট, ISP-র পুল) | ⚠️ **না** — DDNS লাগবে |
| **Static public IP** (আলাদা করে চাইতে হয়) | কখনো বদলায় না | ✅ **হ্যাঁ** |
| **CGNAT** (আপনার এখনকার) | কোনো public IP-ই নেই | ❌ |

### ❌ কী কী এটা বন্ধ করতে পারে

| কারণ | সমাধান |
|---|---|
| **IP বদলে গেল** (রিবুট/ISP পুল) | **DDNS** — No-IP/DuckDNS-এ ফ্রি হোস্টনেম (`farm-bishwas.ddns.net`), রাউটারে DDNS সেট করুন |
| ISP আবার CGNAT-এ ফিরিয়ে দিল | ISP-র সাথে **লিখিত** নিশ্চয়তা রাখুন |
| ISP বদলালেন | নতুন ISP-তেও আবার আবেদন |
| রাউটার বদলালেন/রিসেট | port forward + DDNS আবার সেট |
| ক্যামেরার IP বদলাল | রাউটারে **DHCP reservation** (MAC ধরে) |
| ISP `554` ব্লক করেছে (কখনো হয়) | বাইরের পোর্ট `1554` দিয়ে ম্যাপ |

### 🎯 গুরুত্বপূর্ণ: প্ল্যানটা ২ ভাগে ভাবুন

```
ISP public IP ──► ফার্মের রাউটার ──► ক্যামেরা
                      ↑
              এটাই ভাঙতে পারে (IP বদল)

Contabo VPS ──► MediaMTX ──► সাইট
                      ↑
              এটা ভাঙে না (ফ্ল্যাট সার্ভিস)
```

**VPS-টা "সারাজীবন" ধরনের সেবা** — কনফিগ একবার ঠিক করলে IP বদলালেও শুধু
`mediamtx.yml`-এ একটা লাইন বদলাতে হবে (বা DDNS থাকলে কিছুই না)।

### ✅ সবসময় টিকে থাকার ৫টা অভ্যাস

| # | অভ্যাস |
|---|---|
| ১ | **DDNS ব্যবহার করুন** — `mediamtx.yml`-এ IP-র বদলে `farm-bishwas.ddns.net` |
| ২ | **Static IP-র দাম জিজ্ঞেস করুন** — কেউ ৳৩০০–৫০০/মাসে দেয়, তাহলে DDNS-ও লাগবে না |
| ৩ | রাউটারে **auto-reconnect** চালু রাখুন (লাইন পড়লে নিজেই উঠে) |
| ৪ | Imou ক্যামেরার IP **DHCP-তে বেঁধে** দিন |
| ৫ | **প্রতি মাসে একবার** `canyouseeme.org` + সাইটে লাইভ টেস্ট |

### 💡 그리고 সবচেয়ে বড় কথা — আপনার সিস্টেম ইতিমধ্যেই দুটো পথ জানে

`cameras.cloud_provider` **প্রতি ক্যামেরায় আলাদা**। তাই:

- public IP পেলে → ওই ক্যামেরাটা `none` (VPS)
- IP হারালে বা বদলাল → **সেটিংসে `imou` করে দিন, সাথে সাথে ক্লাউডে চলবে** (< ১ মিনিট)
- **সাইট কখনো বন্ধ হবে না** — শুধু খরচ বদলাবে

> **অর্থাৎ "সারাজীবন" প্রশ্নটা আসলে টাকার প্রশ্ন, বন্ধ হওয়ার নয়।** IP বদলালে
> ভিডিও থামে না — হয় DDNS ঠিক করে দেবেন, নয়তো এক ক্লিকে Imou ক্লাউডে যাবেন।

## ৬.৭ Vercel Pro কি এটা ঠিক করে দেবে? — না

| **Deploy** | `git push` = অটো-ডিপ্লয় ছিল; এখন SSH করে `git pull && build && restart` |
| **১ লাখ ভিজিট** | ২ vCPU / ৪ GB-তে লোড স্পাইক সামলানো কষ্ট — সাইট ধীর হবে |
| **ব্যাকআপ** | Supabase DB নিজে দেখত, ফাইল/আপলোড VPS-এ = আপনার দায়িত্ব |
| **স্প্যাম/সিকিউরিটি** | Vercel-এর WAF/edge নেই — নিজে Caddy + fail2ban |

## ৭. পরের ধাপ — আপনার চূড়ান্ত প্ল্যান

**সিদ্ধান্ত (আপনার):** Vercel-এই থাকবে এখন · শুধু ক্যামেরা সেটআপ · Imou ক্যামেরা ১টা ·

### ⛔ Contabo VPS — এখনই কিনবেন না

public IP হাতে পাওয়ার **আগে** VPS কিনলে সেটা কিছুই করবে না (ক্যামেরা পর্যন্ত
পৌঁছাতে পারবে না), আর টাকা কাটতে থাকবে।

**VPS কেনার সঠিক সময়:** ISP-র কাছ থেকে public IP পেয়ে
`canyouseeme.org`-এ **৫৫৪ = Success** দেখার পর।

### 📅 সময়রেখা

```
দিন ০    ├─ ISP-কে আবেদন ─────────────┐
         ├─ Imou ক্যামেরা অর্ডার ──────┤
         └─ Imou dev অ্যাকাউন্ট ───────┤
                                       │
দিন ২–৪  ক্যামেরা আসে → Imou Life-এ যোগ → RTSP চালু → H.264
         │  (public IP এখনো না এলে)  → cloud_provider = imou  → ✅ লাইভ চলছে
         │
দিন ১–৭  ISP public IP দেয়?
         ├─ হ্যাঁ → port forward → canyouseeme 554 Success → **এখন Contabo কিনুন**
         │        → MediaMTX + Caddy → Vercel ৩টা env → সোর্স none → খরচ ৳০-র দিকে
         └─ না  → Imou ক্লাউডেই চলতে থাকুক, VPS কেনা বাদ
```

### Contabo কেনার সময় যা দেখবেন
